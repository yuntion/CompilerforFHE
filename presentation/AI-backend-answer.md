# 如何使用 AI 生成后端代码？

我的思路是采用“编译器提供约束、AI 生成接口代码、工具验证并反馈修复”的方式。

首先，前端和编译器将模型降级为 FHE IR，确定操作序列、数据依赖、类型以及公开参数与秘密输入。我们计划把这些信息与已经确定的密码参数、目标库版本、函数签名和代码骨架整理为结构化生成任务。AI 的主要任务是把已经确定的计算逻辑实例化为具体密码库调用。

其次，利用 fhe-coder 中的 ReAct Agent 和 RAG 框架，检索目标库的 API 文档与参考实现，为 AI 提供对应版本的调用方式，并限制允许修改的代码区域。例如，计算 y = 1.5x + 0.125 时，输入 x 是 CKKS 密文，常量公开，AI 需要生成目标库对应的乘法和加法调用，并遵守运行时的层级与缩放约定。新增库时，优先让 AI 辅助编写 runtime 适配函数；现有编译器继续负责生成模型的操作序列。

生成后必须调用真实工具检查：先编译、链接并检查接口与密码参数，再进行加密输入、服务端求值、客户端解密，按指定误差容限与参考程序比较。原始明文模型用于衡量整体偏差，同近似的明文参考用于定位密文计算和生成代码引入的误差。服务端代码不能依赖私钥或通过解密完成计算；API 规则检查和参数检查只是验收的一部分，不能等同于安全证明。

如果失败，把编译诊断、失败输入、期望输出和实际输出反馈给 Agent，在有限轮数内修复。验证通过后保留代码、库版本、生成配置和测试报告；超出预算仍不通过则拒绝候选，已有后端可回退到确定性生成路径，新后端仍需完成适配。

当前 CrossFHE 已有确定性 C++ 代码生成与密码库执行路径，fhe-coder 已有 Agent、检索和执行反馈框架。二者的正式生成接口以及真实编译、安全参数检查闭环仍需补齐。因此上述内容是下一阶段具体实现方案，效果要通过与现有生成路径的对照和消融实验来确认。
